# PSD単体と実モデルの資源評価

測定日：2026年10月20日。macOS 27.0.1 / Apple Silicon / Python 3.11.16。実測値は[resources.json](resources.json)、同日のカバレッジは[coverage.json](coverage.json)に保存しています。

## PSDの独立した測定

入力PSDは親プロセスで生成し、各サイズについて新しいPython子プロセスで `import_psd` を1回だけ実行しました。子はAIモデルを読み込みません。入力の読み込み、PSD解析、ラスタ抽出、ZIP生成と返却値の保持を含むプロセスの最大RSSです。依存ライブラリの読み込みも含み、PSD演算だけの追加割当量とは異なります。

| 入力 | 内容 | 読み込み前RSS | プロセス最大RSS | 読み込み時間 |
| --- | --- | --- | --- | --- |
| 1920×1080 | 全画面の通常ラスタ4枚 | 32.8MiB | 116.6MiB | 168ms |
| 3840×2160 | 全画面の通常ラスタ4枚 | 33.1MiB | 309.0MiB | 430ms |

単色・半透明レイヤーから生成したPSDです。調整・効果・複雑な合成を含む実PSDの最大値や、すべての入力に対する上限ではありません。従来の評価プロセス全体のRSSと異なり、入力生成とAIのメモリは含みません。時間は各1回の観測値であり、性能保証には使いません。

## MPSとキャッシュの反復測定

実MobileSAMをMPSで初期化し、512×512の画像を登録・推論・解放する操作を5回ウォームアップ後、100回実行しました。モデルは常駐させ、各回で画像を明示解放し、GCとMPS同期後に測定しました。推論結果は毎回1～3候補であることも検証しました。

| 指標 | ウォームアップ後 | 100回後 |
| --- | --- | --- |
| Python RSS | 447.5MiB | 424.6MiB |
| MPSのテンソル割当量 | 49.3MiB | 49.3MiB |
| MPSドライバーの割当量 | 1187.2MiB | 1187.2MiB |
| 画像キャッシュ件数 | 0 | 0 |
| 削除待ちID件数 | 0 | 0 |

MPSは `torch.mps.current_allocated_memory()` と `driver_allocated_memory()` で測定しました。全100回の解放後サンプルでMPSの両指標は一定、キャッシュと削除待ちIDは0でした。ウォームアップを含む反復部分の実測時間は約25秒です。この範囲では継続的な増加は観測されませんでした。

ドライバー側にはテンソル以外の計算グラフ等も含まれます。モデルやフレームワークが保持する領域を、画像キャッシュの解放漏れとは扱いません。Apple Siliconの共有メモリではRSSとMPS指標を単純加算して総使用量としません。最後の `empty_cache` は計測用であり、製品コードへ各回の強制解放は追加していません。

## 再現手順

完全構成の依存とモデルを[使い方](../../usage.md)に従って配置してから実行します。標準の結果は `reports/resources/resources.json` へ出力します。

```sh
python-service/.venv/bin/python tools/validate_resources.py --cycles 100
```

最低2時間の反復を実施する場合は、次のように指定できます。こちらは今回実行していません。

```sh
python-service/.venv/bin/python tools/validate_resources.py --cycles 100 --seconds 7200 --output reports/resources-2h
```

このツールの反復はモデルとキャッシュの直接呼び出しです。HTTP、Javaクライアント、キャンセル、再起動、PSDの混在を含む長時間試験の代わりにはなりません。数時間のサービス運用、Photoshop由来の実PSD、別PCの測定は残っています。
